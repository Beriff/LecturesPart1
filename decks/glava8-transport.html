8.1 · значение и функции

ПРОТОКОЛЫ
ТРАНСПОРТНОГО
УРОВНЯ

Основными протоколами транспортного уровня являются TCP и UDP. Они предназначены для передачи данных по сети, разделяя их на пакеты установленного размера.

Транспортный уровень — четвёртый в модели OSI — осуществляет передачу сегментов и выполняет роль посредника между уровнем приложений и нижними уровнями.

8.1 · сегментация

СЕГМЕНТАЦИЯ TCP/UDP

С целью передачи больших объёмов данных существует сегментация — разделение данных на меньшие фрагменты, которые затем снабжаются заголовками и передаются по сети.

8.1 · мультиплексирование

МУЛЬТИПЛЕКСИ
РОВАНИЕ

Чтобы предотвратить заполнение всей полосы пропускания одним типом данных, используется сегментация. С помощью мультиплексирования (чередования) сегментов существует возможность передачи большого количества различных данных в одной и той же сети.

8.2 · TCP

ПРОТОКОЛ
TCP

TCP — один из протоколов транспортного уровня. Его главное отличие — обеспечение надёжности доставки данных.

Функции:
  • Отслеживание сегментов, отправленных на узел
  • Подтверждение получения данных
  • Повторная передача при потере
Задачи:
  • Доставка сегментов в одинаковом порядке
  • Установление сеанса связи
  • Регулирование потока передачи данных

НАДЁЖНОСТЬ TCP:
ПОДТВЕРЖДЕНИЕ И ОКНО

В заголовке TCP существует 16-битное поле для указания размера окна — объёма данных, который целевой узел может успешно принять и обработать.

8.2 · повторная передача

ПОТЕРЯ ДАННЫХ И ПОВТОРНАЯ
ПЕРЕДАЧА

Протокол TCP имеет механизм повторной передачи сегментов. Если после истечения таймаута узел-отправитель не получил подтверждение, он повторно отправляет сегменты, начиная с последнего подтверждённого (ACK).

8.2 · завершение сеанса

ЗАВЕРШЕНИЕ
TCP-СЕАНСА

  1. Узел А отправляет сегмент с флагом FIN для прекращения сессии «клиент-сервер»
  2. Узел Б принимает запрос и отправляет подтверждение ACK узлу А
  3. Узел Б отправляет сегмент с флагом FIN для прекращения сессии «сервер-клиент»
  4. Узел А отправляет ответ ACK для подтверждения
8.2 · ISN и управление потоком

ISN И УПРАВЛЕНИЕ ПОТОКОМ

Данные при передаче по TCP делятся на сегменты, которые могут быть доставлены на узел назначения в изменённом порядке. Протокол TCP использует порядковые номера в заголовках каждого сегмента.

ISN
Initial Sequence Number — начальный порядковый номер сеанса. Представляет собой случайное число. ISN не является строго определённым — задаётся случайно, чтобы предотвратить вредоносные атаки.

На узле назначения все полученные сегменты распределяются в правильном порядке и только после этого передаются на уровень приложений.

Зачем случайный ISN?

Если ISN был бы фиксированным (например, 0), злоумышленник мог бы предсказать порядковые номера и подделать сегменты. Случайный ISN защищает от инъекции пакетов.

8.3 · UDP

ПРОТОКОЛ
UDP

Протокол UDP так же, как и TCP, использует сегментацию данных, при этом не задействует процессы подтверждения — что позволяет значительно быстрее передавать данные.

  • Отсутствие установления сеанса связи
  • Отсутствие повторной отправки потерянных сегментов
  • Наличие высокоскоростного потока
8.3 · заголовок UDP

UDP-ДАТАГРАММЫ

Датаграмма — блок информации, передающийся с помощью протокола UDP, без гарантированной доставки. Заголовок UDP содержит всего 8 байт.

8.3 · приложения UDP

ТИПЫ ПРИЛОЖЕНИЙ,
ИСПОЛЬЗУЮЩИЕ UDP

Свои гарантии

Приложения, которые могут самостоятельно гарантировать полную передачу данных, например TFTP. Контроль — на уровне приложения (L7), а не протокола.

Запрос-ответ

Приложения, осуществляющие только отправку запросов и получение ответов, например DHCP.

Реальное время

Приложения для передачи мультимедийного контента в режиме реального времени, например VoIP.

проверь себя

ВОПРОСИКИ

Какие два основных протокола работают на транспортном уровне?
TCP (надёжная доставка с установлением соединения) и UDP (быстрая доставка без гарантий).
Что такое порт и в каком диапазоне он находится?
Порт — идентификатор приложения, 16-битное число от 0 до 65535.
Из каких шагов состоит установка TCP-соединения?
Трёхэтапное рукопожатие: 1) SYN → 2) SYN+ACK → 3) ACK.
Чем отличается размер заголовка TCP от UDP?
Заголовок TCP — 20+ байт (порты, seq, ack, флаги, окно, опции). Заголовок UDP — всего 8 байт (порты, длина, контрольная сумма).
Какие флаги TCP вы знаете?
SYN (синхронизация), ACK (подтверждение), FIN (завершение), RST (сброс), PSH (push), URG (срочность).
Какие приложения используют UDP и почему?
TFTP (свои гарантии на L7), DHCP (запрос-ответ), VoIP (реальное время). UDP быстрее, т.к. не тратит время на установку соединения и подтверждения.

Транспортный уровень обеспечивает доставку данных конкретному приложению через порты и сокеты. TCP гарантирует порядок и целостность. UDP жертвует гарантиями ради скорости.
