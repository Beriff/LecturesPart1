Основные протоколыуровня приложений · 01–06

Во время сеанса связи протоколами уровня приложений пользуется как отправляющая, так и принимающая сторона. Для успешного обмена информацией между двумя приложениями необходима совместимость протоколов.

01
HTTP
HyperText Transfer Protocol
Протокол передачи гипертекстовых документов. Позволяет получать различные ресурсы, HTML-документы. Лежит в основе обмена данными в сети Интернет.
02
HTTPS
HyperText Transfer Protocol Secure
Защищенный протокол передачи гипертекста. В отличие от HTTP использует шифрование для безопасного подключения.
03
DNS
Domain Name System
Служба доменных имен. Преобразует доменные имена узла в IP-адреса, например, eltex-co.ru – в 62.109.1.166.
04
DHCP
Dynamic Host Configuration Protocol
Позволяет сетевым устройствам автоматически получать IP-адрес и другие сетевые параметры, необходимые для работы в сети.
05
FTP
File Transfer Protocol
Протокол передачи файлов по сети. Построен на архитектуре «клиент-сервер». Позволяет получать доступ на другой узел и обмениваться данными.
06
SFTP
SSH File Transfer Protocol
Защищенный протокол передачи файлов: те же задачи, что и FTP, но поверх надежного и безопасного соединения.

Основные понятияFTP

Протокол передачи файлов (FTP) необходим для передачи данных между FTP-клиентом и FTP-сервером.

FTP-клиент — запущенное на узле приложение для получения данных с сервера и отправки данных на сервер. На сервере также должна быть запущена FTP-служба в виде приложения.

Для работы FTP необходимо два соединения:

  1. 01
    для передачи команд клиента и ответов сервера устанавливается TCP-соединение;
  2. 02
    для передачи файлов устанавливается TCP-соединение. Оно создается для каждого сеанса передачи данных и автоматически закрывается после завершения передачи.
12

FTPрежимы ASCII и бинарный

FTP использует архитектуру клиент/сервер (C/S). FTP-клиент устанавливает соединение TCP с FTP-сервером, после чего файлы можно выгружать и загружать. FTP поддерживает два режима передачи:

Режим ASCII

Для текстовых файлов (TXT, LOG, CFG). Отправитель преобразовывает символы в формат кода ASCII перед отправкой; получатель преобразует их обратно в символы.

Рекомендуется для передачи файлов конфигурации и лог-файлов сетевых устройств.

Бинарный режим

Для нетекстовых файлов (BIN, EXE, PNG) — изображений и исполняемых программ. Отправитель передает файлы без преобразования формата.

Рекомендуется для передачи файлов версий сетевых устройств.

13

Активный режимработы FTP

В активном режиме клиент FTP использует случайный порт (больше 1024) для запроса на соединение на порт 21 FTP-сервера. Сервер устанавливает управляющее соединение.

FTP-клиент прослушивает порт Р (другой случайный порт больше 1024) и командой PORT уведомляет сервер.

Когда нужно передать данные, сервер отправляет запрос на соединение с порта 20 на порт P клиента.

ПортНазначение
21управляющее соединение (от клиента к серверу)
20соединение для данных (от сервера к клиенту)
Pслучайный порт клиента > 1024
14

Пассивный режимработы FTP

Начало то же: запрос на порт 21 и управляющее соединение. Клиент прослушивает порт Р и командой PASV уведомляет сервер.

Сервер включает порт N (случайный, больше 1024) и командой Enter PASV сообщает его номер.

Когда нужно передать данные, клиент отправляет запрос на соединение с порта Р на порт N сервера.

ПортНазначение
21управляющее соединение
Nпорт данных сервера > 1024 (открывает сервер)
Pпорт клиента > 1024 (инициатор соединения)

Основные понятияTFTP

По сравнению с FTP, TFTP предназначен для передачи небольших файлов, и его проще реализовать.

  • Использование UDP (порт 69) для передачи;
  • Аутентификация не требуется;
  • Возможен только запрос файла с сервера или выгрузка файла на сервер; просмотр каталога файлов на сервере невозможен.

TFTP поддерживает пять форматов пакетов:

DATAпакет передачи данных

ERRORпакет контроля ошибок

Сценарии примененияTelnet

Чтобы упростить управление устройствами с помощью команд, можно использовать Telnet.

Управление через Telnet отличается от управления через консольный порт: выделенный кабель не требуется, если IP-адрес сервера Telnet доступен и клиенты могут обмениваться данными с портом 23 TCP сервера Telnet.

Устройство, которым управляют через Telnet, — сервер Telnet, устройство, которое подключается, — клиент Telnet. Многие сетевые устройства могут быть и тем, и другим.

Предпосылки:Всемирная паутина WWW

На начальном этапе развития Интернета для обмена документами предлагалось использовать Всемирную паутину (World Wide Web, WWW).

WWW состоит из трех частей:

HTML

язык гипертекстовой разметки для отображения содержимого документа в браузере

HTTP

передача документов по сети

URL

WWW было названием клиентского приложения для просмотра HTML-документов, а теперь это набор технологий (HTML + HTTP + URL-адрес), широко известный как Интернет.

19

Доступ к веб-страницес помощью браузера

При вводе унифицированного указателя ресурсов (URL) браузер получает данные с веб-сервера и отображает контент на странице.

HTTP — протокол прикладного уровня для связи между клиентским браузером или другой программой и веб-сервером. HTTP основан на типовой архитектуре клиент/сервер и использует TCP для передачи.

URL-адрес однозначно определяет местонахождение веб-страницы или других ресурсов в Интернете. URL может содержать имя страницы гипертекста — обычно с расширением .html или .htm.

20

ПротоколыHTTP и HTTPS

HTTP реализован по принципу «запрос-ответ». Существуют три метода сообщений, отправляемых от клиента (браузера):

  1. 01
    GET — запрос данных клиентом: например, при вводе URL в строке браузера отправляется GET-запрос для получения страницы.
  2. 02
    PUT — отправка на веб-сервер ресурсов и контента: создание новых ресурсов или обновление существующих (профиль, изменения в документах).
  3. 03
    POST — отправка на веб-сервер файлов данных, больших объемов информации. Повторные POST-запросы могут создать несколько одинаковых ресурсов.
21

HTTP небезопасен,HTTPS — решение

К сожалению, протокол HTTP не обеспечивает безопасности: сообщения запроса/ответа передаются открытым текстом без шифрования, что позволяет нарушителям перехватывать данные пользователей.

Для защищенного обмена данными между узлами была придумана модификация HTTPS (HTTP Secure). Она обеспечивает аутентификацию и шифрование данных между узлами.

Как работаетHTTP

  1. 01
    Браузер делит веб-адрес на три части: http/https (протокол), www.eltex-co.ru (имя сервера), index.html (запрашиваемый файл);

  3. 03

  4. 04

  5. 05

HTML — стандартизированный язык гипертекстовой разметки документов. Он нужен, чтобы браузер понимал, как отобразить веб-страницу.

Взаимодействие протоколовс приложениями пользователей

От HOSTS.txtк DNS

ARPANET, предшественник Интернета, сопоставлял имена хостов с IP-адресами одним файлом HOSTS.txt, за который отвечал сетевой информационный центр (NIC).

После перехода ARPANET на TCP/IP пользователей стало резко больше, и поддерживать файл вручную стало очень сложно:

Конфликт имен

трудно гарантировать, что имена хостов не совпадут с уже используемыми.

Согласованность

имена могли измениться несколько раз до того, как HOSTS.txt текущего хоста обновлялся.

Поэтому была введена DNS.

26

Служба доменных именDNS

При вводе доменного имени в браузере имя определяется в IP-адрес — фактически браузер взаимодействует с этим IP-адресом. Протокол для этого — Система доменных имен (DNS).

Запомнить столько IP-адресов трудно, поэтому DNS сопоставляет IP-адресам буквенно-цифровые доменные имена. Например, проще обращаться к eltex-co.ru, чем к 62.109.1.166. Если IP-адрес изменится, пользователь этого не заметит.

Для работы разрешения имен на сетевом интерфейсе должен быть указан IP-адрес DNS-сервера.

Имя в IP

eltex-co.ru ‹=› 62.109.1.166

IP в имя

62.109.1.166 ‹=› eltex-co.ru
DNS работает в обе стороны

36

Рекурсивныйи итеративный запрос

DNS — распределенная система: база данных большинства DNS-серверов не содержит всех записей. Если у сервера нет записи, запрос выполняется одним из способов:

Рекурсивный запрос

DNS-сервер запрашивает другие DNS-серверы и возвращает результат запроса DNS-клиенту.

Итеративный запрос

DNS-сервер сообщает DNS-клиенту IP-адрес другого DNS-сервера, с которого клиент сам запрашивает доменное имя.

37

Доверенныеи недоверенные DNS-серверы

Доверенный (авторитетный)

Хранит оригинальные записи о соответствии доменных имён и IP-адресов в рамках своей зоны ответственности и имеет право выдавать авторитетные ответы: информация актуальна и достоверна.

Недоверенный (неавторитетный)

Не имеет оригинальных записей: перенаправляет запросы клиентов к вышестоящим серверам и запоминает ответы. На повторный запрос отвечает из памяти, не загружая корневые серверы.

Авторитетные данные хранятся в базе в рамках зоны ответственности; за них отвечает доверенный сервер. Неавторитетные данные получены перенаправлением к доверенному серверу и записаны в память локального DNS-сервера.

38

Флаг AA:авторитетный ответ

Интуитивно кажется, что неавторитетные данные недостоверны. Однако флаг AA отражает два состояния:

AA = 1

данные получены от сервера, который отвечает за эту область данных.

AA = 0

выданы из памяти локального DNS-сервера, который записал их при получении от доверенного сервера.

Актуальность данных обеспечивается периодической очисткой памяти локального DNS-сервера с последующим обновлением у доверенных серверов.

В анимации «Путь DNS-запроса» авторитетный сервер отвечает с AA=1, а роутеру и компьютеру ответ приходит уже с AA=0 — из памяти сервера провайдера.

Проблемыручной настройки параметров сети

Пользователи

Обычные пользователи не знакомы с сетевыми параметрами — частые неправильные конфигурации приводят к сбою подключения к сети.

Конфликты

Случайная конфигурация IP-адресов может вызвать конфликты IP-адресов.

Нагрузка

Администраторы настраивают параметры централизованно, с большими нагрузками и повторяющимися задачами.

Планирование

Администраторы должны заранее спланировать и выделить IP-адреса пользователям.

40

Низкий коэффициентиспользования IP-адресов

Фиксированные адреса

В корпоративной сети каждый пользователь использует фиксированный IP-адрес. Коэффициент использования адресов очень низкий: некоторые адреса остаются неиспользованными длительное время.

Беспроводные сети (WLAN)

WLAN обеспечивают гибкое расположение станций (STA). При перемещении STA из одной зоны покрытия в другую может потребоваться повторная настройка IP-адреса.

Протокол динамическойконфигурации узла DHCPv4

DHCP нужен для автоматического назначения сетевых параметров узла: IPv4-адреса, маски подсети, адреса DNS-сервера, шлюза по умолчанию. Без них работа в сети невозможна, поэтому этот сервис используется первым.

Статическая адресация

Параметры вручную — для серверов и принтеров.

Динамическая адресация

В больших сетях, где количество устройств постоянно меняется. Обычно включена на интерфейсе по умолчанию.

Узел подключается к сети и запрашивает адрес; DHCP-сервер выдает свободный адрес из диапазона — пула адресов. Дома DHCP-сервер — домашний маршрутизатор, в средних и крупных сетях — отдельный компьютер.

Конфликт IP-адресови методы его предупреждения

Два узла с одним IP-адресом — малореально, но возможно: например, когда адреса вручную назначают разные администраторы без общей политики и документации. Тогда ни одно из устройств не получит информацию корректно.

Во избежание конфликта клиент после DHCPACK отправляет ARP-запрос на полученный адрес. Нет ответа — адрес уникален. Пришел ARP-ответ — адрес занят, и клиент отправляет DHCPDECLINE.

46

Продление арендыIP-адреса

При получении адреса и времени аренды DHCP-клиент назначает себе два таймера: T0 = 50 % и T1 = 87,5 % от времени аренды.

  1. 01
    При T0 — одноадресный DHCPREQUEST серверу, выдавшему адрес. Сервер жив — DHCPACK, таймеры обновлены.
  2. 02
    Нет ответа — адрес используется до T1, затем DHCPREQUEST широковещательно.
  3. 03
    Сервер так и не ответил до истечения аренды — снова DHCPDISCOVER.
  4. 04
    Сервер может отказать: DHCPNACK — и клиент начинает новый цикл с DHCPDISCOVER.

Протокол обмена блокамисерверных сообщений SMB

SMB предназначен для передачи данных между клиентом и сервером. Он определяет организацию совместных ресурсов в сети: директории, файлы, принтеры и прочее. С его помощью можно:

  • запускать, аутентифицировать и завершать сеансы;
  • управлять доступом к файлам, каталогам и т.д.;
  • разрешать приложению отправлять данные на другое устройство.

В отличие от FTP, SMB обеспечивает долговременное подключение: пользователь получает доступ к файлам на другом узле так же, как у себя.

49

ПротоколыSMTP, POP и IMAP

Электронная почта — система для отправки, хранения и получения сообщений по сети. Письма хранятся на почтовых серверах в базах данных; серверы обмениваются сообщениями между доменами.

SMTP — отправка от клиента до сервера и с сервера на другой сервер. POP или IMAP — получение сообщения.

50

Работа протоколаSMTP

SMTP-сообщение состоит из заголовка и тела. Заголовок имеет строго определенный формат (RFC 2822), тело может содержать текст произвольной длины.

При отправке на почтовый сервер устанавливается соединение. Сервер либо отправляет сообщение получателю (если он в списке получателей этого сервера), либо пересылает другому почтовому серверу.

Сервер назначения недоступен

Сообщение временно хранится на почтовом сервере и периодически отправляется повторно. Не доставлено за определенное время — возвращается отправителю с уведомлением. Поиск нужных почтовых серверов — с помощью DNS.

51

ПротоколPOP

POP используется для получения электронных сообщений от почтового сервера. После установки соединения сервер отправляет приветствие, и происходит обмен данными.

Важно: при получении сообщения пользователем оно удаляется с почтового сервера. Это может быть критично для компаний малого бизнеса.

52

ПротоколIMAP

IMAP также позволяет получать сообщения с почтового сервера по порту TCP 143, но, в отличие от POP, пользователь получает копию сообщения.

Исходное сообщение остается на сервере, пока не будет удалено вручную. Удаление происходит и у пользователя, и на почтовом сервере.

Требованияк синхронизации времени

Во многих сценариях корпоративных сетей требуется последовательная синхронизация всех устройств:

Управление сетью

анализ журналов и сообщений отладки, собранных от различных маршрутизаторов.

Система тарификации

часы всех устройств должны быть согласованными.

Совместная работа систем

единый синхронизирующий сигнал обеспечивает правильную последовательность событий.

Резервное копирование

Системное время

время входа пользователей и изменения файлов.

54

Протоколсетевого времени NTP

Устройства используют программные часы, запускаемые при загрузке. Время на всех устройствах должно быть синхронизировано — это важно для безопасности и диагностики: при разном времени найти причину события в сети затруднительно.

Время можно ввести вручную командой или получить по NTP: все устройства получают одинаковые настройки времени от NTP-сервера.

В NTP используется иерархия источников времени; каждая ступень — часовой слой (stratum).
